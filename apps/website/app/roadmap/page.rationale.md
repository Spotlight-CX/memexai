# Roadmap page rationale

## Target persona

**Primary:** Potential adopter evaluating whether MemexAI will grow to fit their needs. They have a feature gap today (e.g., Python SDK, LangGraph adapter, managed hosting) and want to know if it's coming before committing.

**Secondary:** Existing user who wants to understand priority and contribute feedback on what matters most.

## Page goal

Visitor sees that the product is actively maintained, understands what's next vs what's longer-term, and either feels unblocked or submits feedback. Conversion = reduced churn risk from "missing feature" objections.

## Section rationale

### Status buckets (shipped / in progress / planned / considering)
- **Goal:** Honest state of the product. "Shipped" builds credibility. "Considering" sets honest expectations without over-promising.
- **Design choices:** Four buckets is the right granularity — more granular (e.g. "Q3 2026") becomes stale and erodes trust. Less granular (just "planned" vs "done") doesn't help the evaluator.

### Feedback / request signal
- **Goal:** Surface the Slack or GitHub link prominently — the roadmap should invite input, not be a one-way broadcast.
- **Design choices:** Every roadmap item should ideally link to an issue or discussion thread so users can upvote or follow.
